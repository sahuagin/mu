# Codex CLI internals — the TUI commitment model, and what transfers to mu-solo

*Research writeup, 2026-08-27. Source: `github.com/openai/codex` at trunk
`694edc23b22b` (2026-08-27), checkout at `~claude/src/codex`. This re-does,
durably, a UI-focused investigation from ≈2026-07-07 whose session was lost
(transcripts pruned; the session reportedly ended in a hang that took the
focus). An Aug 4 session also compared codex's TUI against mu-solo's
scrollback trouble and recorded a design on the streaming bead; this document
grounds that comparison in the current source.*

## Scale, first

`codex-rs` is now a 115-crate workspace, and `tui/src` alone is ~77k lines
(160 top-level modules). The headline lesson is unchanged from the Aug 4
finding: codex's UI never has the "collapse moment" because it pays a large
engineering cost upstream so the moment cannot exist. The rest of this
document is what that cost buys and which parts are load-bearing.

## The UI architecture

### 1. Terminal scrollback IS the finalized transcript

`tui/src/insert_history.rs` states it outright: "Codex uses the terminal
scrollback itself for finalized chat history, so inserting a history cell is
an escape-sequence operation rather than a normal ratatui render." ratatui
owns only a small inline viewport at the bottom (composer, status, the live
region). Finalized content is written **once**, above the viewport, via
crossterm escape sequences, and never touched again. Consequences:

- Native scrollback, native selection/copy, no alternate screen in the main
  flow.
- Nothing on screen ever moves when a turn completes — the text stays where
  it streamed, the prompt stays at the bottom.
- Resize cannot corrupt history: history is the terminal's problem after
  commit. Codex chooses per insertion between `HistoryLineWrapPolicy::PreWrap`
  (codex wraps before writing) and `::Terminal` (let the terminal soft-wrap),
  and has an `InsertHistoryMode::FullScreen` fallback for terminals with
  unreliable scroll regions (comment names Zellij), which preserves
  terminal-managed wrapping.
- The cost: `custom_terminal.rs` is a fork of `ratatui::Terminal` to make the
  inline-viewport + above-viewport insertion model work, and the escape
  choreography (SavePosition / scroll region / RestorePosition) is its own
  maintained subsystem with hyperlink remapping and wrap-aware line handling.

### 2. Committed cells vs one mutable active cell

`chatwidget.rs`: the UI has committed transcript cells (finalized
`HistoryCell`s) and **one** in-flight active cell that may mutate in place
while streaming (often a coalesced exec/tool group). The moment content is
final it is committed and leaves the mutable domain. The transcript overlay
(Ctrl+T) renders committed cells plus a *cached* live tail derived from the
active cell; the cache key incorporates the active-cell revision and
animation ticks, so the overlay refreshes without rebuilding on every draw.
The discipline is a single mutation frontier: exactly one thing on screen is
allowed to change, and everything behind it is immutable.

### 3. The streaming pipeline has an explicit commit boundary

`tui/src/streaming/` + `markdown_stream.rs`:

- `MarkdownStreamCollector` buffers raw token deltas and exposes a commit
  boundary **at each newline**. Only the completed-line prefix is ever
  committable; the trailing partial line stays in the buffer for the next
  delta. Partial lines structurally cannot reach scrollback.
- Committed lines enter a FIFO queue stamped with arrival time. `chunking`
  computes adaptive drain plans from queue pressure and oldest-queued age;
  `commit_tick` binds those policy decisions to concrete drains. Bursts drain
  fast, trickles stay smooth, and the policy code reasons about age without
  peeking at text. The stated key invariant is queue ordering: all drains pop
  from the front.
- The collector does not parse markdown; it defines stable source boundaries.
  Rendering lives in the controllers so a width change re-renders from one
  accumulated source string. `table_holdback` keeps half-streamed markdown
  tables out of the commit stream.

### 4. Replay and snapshot testing keep it honest

The TUI has its own JSONL session log (`tui/src/session_log.rs`) and a replay
path (`chatwidget/replay.rs`): `replay_thread_turns()` rehydrates turns into
transcript state while suppressing live-only side effects, marking replayed
events by passing ids as `None`. Snapshot test suites sit next to the
streaming and rendering modules (`streaming/snapshots`,
`chatwidget/snapshots`). The transcript pipeline is a pure-enough function of
the event stream that it can be regression-tested headlessly.

## What transfers to mu-solo

The Aug 4 session already converged on this architecture independently
("scrollback fixed until commit" — recorded on the streaming bead as the
authoritative design, driver recorded as blindness, not preference). Codex
validates it at production scale and supplies the parts list. Load-bearing
invariants, in dependency order:

1. **Single mutation frontier.** Committed content is immutable and lives in
   the terminal's scrollback; exactly one active cell may mutate; commit is a
   one-way door. Every scrollback bug class mu-solo has fought comes from
   letting more than one region change.
2. **Newline-gated commits.** A partial line is never committed anywhere. The
   stream buffer owns the tail; the live region renders it; scrollback only
   ever receives whole lines.
3. **Exactly-once insertion above the viewport.** History insertion is an
   escape-sequence operation with an explicit wrap policy per insertion, not
   a re-render. Budget for a fallback mode — codex ships one specifically for
   multiplexers with unreliable scroll regions.
4. **Pressure-adaptive drain.** Commit pacing is a policy over (queue depth,
   oldest age), not a fixed tick. This is what makes fast models not feel
   janky and slow models not feel dead, with bounded work per tick.
5. **Replay as the test harness.** mu already has the session event log as
   the single source of truth; mu-solo's renderer should be a function of
   that log, replayable headlessly with side effects suppressed, and
   snapshot-tested. Codex needed to add a TUI-side log to get this; mu gets
   it from `SessionEventLog` for free.

The honest cost estimate: codex spends tens of thousands of lines here,
including a forked ratatui Terminal. mu-solo does not need the whole surface
(overlays, backtracking, per-cell animation), but items 1–3 are not optional
if the scrollback model is to hold — they are one design, not three features.

## Non-UI notes worth having on file

- **SQ/EQ protocol.** The client↔agent protocol is an explicit Submission
  Queue / Event Queue pair (`protocol/src/protocol.rs`) — commands in, events
  out, fully async. Same posture as mu's command-journal + event-log design
  (mu-046): no request/response mutation surface.
- **Rollouts.** Per-thread JSONL rollout files under a sessions dir with an
  archived subdir, cursor-paginated listing, and interactive-session source
  tagging (`codex-rollout` crate) — codex's analog of mu's per-session event
  JSONL, used for resume/fork (`replay_thread_turns` consumes it).
- **Convergent evolution: agent roles.** `agent-roles` is a crate that loads
  role definitions from config files (`AgentRoleConfig`,
  `load_agent_roles`, discovery of role files) — the same shape as mu's
  `agent_roles.toml` + `agent-role` resolver. Multi-agent surface exists
  in-protocol (`MultiAgentMode`, `CollaborationMode`, delegation via
  `codex_delegate`, trusted-skill propagation to delegated workers landed the
  day of this snapshot).
- **The platform drift.** Since the January-era codebase, the workspace grew
  app-server (JSON-RPC daemon + client for IDE/automation), cloud-tasks,
  agent-graph-store, code-mode (tool-calls-as-code), dynamic tools + a plugin
  catalog surfacing in the TUI, hooks RPC, and an `agents_md_manager` (AGENTS.md
  as a managed subsystem). Codex is on the same framework-ization trajectory
  the DeepSeek Harness writeup describes, but product-first: the seams are
  internal crates, not user-swappable plugins.
